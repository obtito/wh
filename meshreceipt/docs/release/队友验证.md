# 队友跨机器验证步骤

接收核心交付目录或压缩包后，先经团队可信渠道确认工具版本与以下原交付身份。文档附带身份本身不是新的信任根。

- 合格交付服务：0x89b55cA3dd9F2b5ADd33A61504B3B531589D5c36，careful-demo。
- FAIL 取证服务：0xf59e678daF69F9CB023083C2E96264ae6BFb111c，rapid-demo。
- 原服务实例：819eea82-7664-4f53-b9cc-101982158359。

在另一台机器解压后执行：

```sh
npm ci --ignore-scripts
npm run handoff:check -- recipient-result.json
npm run build
npm start
```

检查生成的 recipient-result.json：qualified 为 PASS、failure 为 FAIL、tamperRejected 为 true，并有 10 个节点、1 个网格和 1 个动画。终端打印提取模型所在目录。

在自己的 GLB 查看器或网页项目打开提取的 model.glb，确认模型和动画实际可见。可以用独立的 three-gltf-viewer，也可用已有工具。截图或短录屏记录打开过程。只看 NodeIO 读取结果不算浏览器导入。

确认后补充浏览器和版本、实际执行机器、打开成功与否、截图位置和失败原因。脚本默认把 browserOpened 和 externalComputerConfirmed 设为 false，不能把自动运行当作这两项已经确认。将结果及经本人同意分享的截图交回团队；不必提供设备序列号、私钥或无关文件。

网络安装失败时保留错误；不能假设已拥有作者的缓存。输出文件不覆盖，重跑时使用新的结果文件名。存在问题先反馈具体错误，不关闭签名、文件一致性或复算检查。
