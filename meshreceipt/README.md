## 运行

需要 Node.js 22.9+（已在 Node 24.19 验证）。依赖锁定在 `package-lock.json`。

```sh
npm ci --ignore-scripts
npm test
npm run build
npm start
```

打开 http://127.0.0.1:4318 。开发模式为 `npm run dev`，前端 http://127.0.0.1:5173 代理后端 4318。只监听本机，不应直接暴露公网。

已有服务正在运行时，可使用独立演示入口：

```sh
npm run demo:isolate
```

它加载本机 `.env`，在忽略的 `data/isolated-demos/session-*` 创建独立构建和 `private-store`，使用自动分配的回环端口，不覆盖 `dist/` 或读取原实例任务。启动本身不调用模型；网页每次实时任务仍需数据/费用确认。终端打印本次 URL，关闭终端不会删除已保留证据。不要分享整个会话目录或私钥，只分享审核过的交付物。构建为启动时快照，代码变更后另建隔离实例，不假定旧实例自动更新。

演示：运行验收演示 → 创建任务 → 故障服务真实删除动画，FAIL → 换服务 PASS → 下载报告或复算 → 再建同类任务，引用此前记录并优先选通过服务。已有记录时首次也可能直接通过，这是历史复用。两个服务和验收器均由团队控制，签名不证明独立性，少量记录不是总体信誉评分。收藏仅保存在当前浏览器，不是链上持有。

任务/报告/样例和本机演示身份私钥保存在被忽略的 `data/`。私钥文件权限 0600；不要提交或分享整个目录。重启保留已完成记录，中断任务标记 INTERRUPTED。处理使用子进程、30 秒超时、256 MB JS 堆限制及 4 任务队列；这不是强安全沙箱。

CLI 仍可独立使用：

```sh
npm run fixtures
npm run verify -- data/fixtures/original.glb data/fixtures/good.glb data/fixtures/policy.json
```

`fixtures` 会生成项目自有程序化模型及纹理，写入忽略的 `data/fixtures/`，不依赖第三方模型素材。交付模型通过实际纹理降采样生成；故障注入实际删除动画或改变关键帧。

CLI 参数为原模型、交付模型、事前确定的规则文件、可选报告输出路径。可选报告文件使用独占创建，不覆盖已有文件。

退出码：0=PASS，1=FAIL，2=INCONCLUSIVE，3=ERROR。它可以作为 GitHub Actions/其他 CI 的检查步骤，不要求区块链。

## 支持范围与规则

- GLB 2.0，最多 10 MiB；内嵌 PNG/JPEG；节点、网格、动画须具有唯一非空名称。
- 三角形网格、LINEAR/STEP 的节点 TRS 动画。暂不支持扩展、外部/data URI、骨骼、Morph、相机和稀疏访问器。
- `meshreceipt.texture-only.v1` 始终检查格式、文件大小、指定节点、层级、几何属性/索引和动画数据。不能通过规则关闭这些检查。
- 纹理处理仅降采样，不优化网格/动画。图像解码设置像素上限。
- 当前几何/动画比较是限定范围内的严格数据比较，不是通用视觉/语义等价算法；不能证明版权、原创、美观或所有渲染器兼容性。
- 当前 manifest 未比较材质参数、材质绑定及纹理内容；已实际确认将材质改成完全透明仍可通过现有检查。PASS 仅指列出的规则通过，不代表视觉保真或完整质量合格；本轮交付包修复没有扩大验收规则。
- 不支持的内容返回 INCONCLUSIVE；原文件无效不能作为可信基准；交付损坏返回 FAIL；工具调用异常由 CLI 返回 ERROR。

## 报告与复核

报告绑定原文件 SHA-256、交付 SHA-256、规则 SHA-256、验收器/依赖版本、逐项结论和规范化报告哈希。不含运行时间或路径，以保持同一环境内可复算。数组保持定义顺序，对象键排序。

来源签名采用 EIP-191，绑定应用实例、任务/尝试、服务、输入/输出/规则指纹；两个演示身份由本机生成，不是实名或跨链通用凭证。报告可以重新执行验收并对照哈希和签名。没有事前链上规则承诺、独立第三方验证、公共持久化保证或零知识证明。

## 离线交付与独立消费

新建自有样例任务后，完成尝试下方可确认导出原文件和结果。PASS 支持“合格交付包”，FAIL 仍支持“履约取证包”，两者分开；导出会重新验收，不只读取旧 PASS 标记。重启本轮后端后新导出为 v2：五份数据材料加 `README.txt` 使用说明，绑定来源声明、文件指纹及发布签名，不包含私钥、原任务说明或整个数据库。消费工具仍支持 v1 五文件包，旧包不重签、不自动改成 v2；旧任务缺少冻结授权时须重建，不自动追授来源许可。

另一使用者使用可信工具版本，按页面或随包说明给出的 `npm run consume -- ... --issuer ... --instance ... --provider ... --out ...` 命令完成离线核验和提取，输出 `model.glb` 可供查看器读取；身份须经可信渠道确认，不能只抄包里的公钥。工具源码及锁定依赖须另取；安装需要网络，消费过程不请求网络。提取新增 `seal.json`，保留原发布签名；请保留整个提取目录或原 JSON 包。输出目录必须不存在。退出码 0 为合格，1 为已验证 FAIL 取证，2 为其他非合格取证，3 为验证/操作错误。

详细格式、使用步骤与测试边界见[交付包 v2 与 v1 兼容说明](docs/交付包-v1.md)。读取会拒绝 FIFO 等特殊输入文件，提取保留签名。这是离线分发能力，不代表公开托管、版权认证、主网存证或历史记录已经跨实例自动导入。

## 可选实时 Agent 与链上记录

根据 `.env.example` 在本机创建被忽略的 `.env`，配置 OPENAI_API_KEY 后正常构建并重启。默认模型为 `gpt-6-astra`、`OPENAI_REASONING_EFFORT=medium`；可显式改为 `max`，但不自动提高超时或 token 上限。显式配置的 OPENAI_MODEL 仍被保留。不要将密钥发到聊天或写入前端，提交源代码/压缩包时也须排除 `.env`。页面明确区分“未配置”与“已配置、连接未验证”，存在配置不证明能调用该模型。本机已在用户授权下配置后端密钥与 Astra/medium，`.env` 权限为 0600。此前连接官方地址失败，不能据此判断密钥无效；用户提供对应中转端点后，已完成一次真实联网样例验证，结果见下文。该结果不证明直接连接 OpenAI 官方 API 成功。

依据 [OpenAI 官方推理参数](https://developers.openai.com/api/docs/guides/reasoning)，每轮 Responses 请求显式发送 `reasoning: { effort: "medium" }`（或本机选定档位）。本适配器接受 low/medium/high/xhigh/max；`ultra`、`none`、`minimal`、`1.5` 等在请求前拒绝，不自动转换档位、算力、服务层或费用倍率。切换档位需要重启后端并创建新任务；一个任务内保持固定配置。API 配置及任务摘要只展示请求的模型/档位，不声称已核验服务实际使用的内部模型。

适配器按 [OpenAI 官方工具调用协议](https://developers.openai.com/api/docs/guides/function-calling) 使用 strict schema、关联 call_id、保留 Responses 输出及串行工具；依据[无服务端保存的推理上下文说明](https://developers.openai.com/api/docs/guides/reasoning)在内存中回传全部 output，不将私有推理持久化。首次请求强制 query_records，执行器也独立检查先查询、白名单和精确参数；最多 6 轮、每次 API 25 秒、每轮 1800 输出 token、两个不同服务，拒绝重复 call_id 和并行调用。实际代码验收 PASS 后停止，两个服务耗尽也停止。口头 PASS、工具返回的自报 PASS 都不能替代已完成的代码验收；API 出错不静默切换演示。

模型只看中性 `service-a` / `service-b`、服务 A/B、相同范围说明与模拟成本。旧签名中的 `rapid-demo` / `careful-demo` 保留，仅由执行器映射，不向模型泄露 ID 中的角色提示、故障参数、私钥或老名称。历史只投影必要摘要，并注明 `local-cache-not-independently-reverified`；这不完成 GCC 的独立历史复用验证。

实时模式每个任务需勾选数据/费用确认，修改说明或切换模式会清空确认；API 同样要求 `confirmModelData: true`，否则创建前拒绝。发送范围为资产标题、任务说明、规则、中性服务目录与本机历史摘要，不含 GLB 或私钥。配置的自定义端点须可信，仅允许 HTTPS/本机 HTTP，拒绝 URL 账号、查询参数及片段，并禁止请求跟随重定向。

任务保留 `meshreceipt.agent-run.v1` 调用摘要：请求模型名、请求推理档位、响应 ID、token 用量（若 API 提供）、工具/中性服务与拒绝/执行/验收结果；旧任务未记录档位时明确显示未提供。界面显示摘要，不保存原始 API 响应、密钥或私有推理。这是本机执行日志，不是第三方模型证明；注入的模拟 fetcher 明确标为 `test-fixture`。调用摘要不自动加入模型交付包，避免把任务上下文混入分发材料。
